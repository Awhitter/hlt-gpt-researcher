# File a Linear story

Writing to Linear is a real action. Treat it like one.

## Before

Say exactly what you are about to file or change, and wait for a yes. One issue
per call — there is no bulk verb and there should not be.

## The issue itself

Required, because this board already has dozens that lack them and they rot in
triage:

- **what** — the change, in a sentence someone outside the thread understands.
- **why** — the problem it solves, not the solution restated.
- **done when** — how we would know it is finished.

Put it in the right project and label it `repo:nursing-mastery` (or the correct
repo). An issue with no project and no label is invisible.

Alec writes titles as problem statements — "Four padlocks, one key". Match that
voice when he is the requester; write plainly for everyone else.

## After

Paste the before and the after. The thread is the receipt. If you changed
something you did not fully understand, say so at the time, not later.
