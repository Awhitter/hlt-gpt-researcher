Grounding Context

Codebase Context. This repo is a fork of Assaf Elovic's GPT Researcher, branded Mastery Research. HLT behavior is supposed to live in overlay modules (hlt_*.py), not in broad edits to upstream core. A Monday workflow merges upstream master into a sync/upstream-* PR, runs two HLT tests on clean merges, and pastes a static overlay checklist into the PR body. The live docking fuse is one import at the end of backend/server/app.py that calls install_hlt_extensions(app).

Katailyst already has three doors into this service: MCP tools whose names match upstream gptr-mcp, HTTP /gather (today a thin quick_search adapter with no research_id), and Brain/library routes. REST /api/quick_search is a documented web-only exception that does not mount codegraph or Katailyst presets. Codegraph is an in-repo GitNexus sidecar on Render (hlt-codegraph). Cleo's Slack body runs on Hermes (hlt-hermes) and mounts five MCP servers: gpt-researcher, codegraph, katailyst2, Linear, PostHog. InfraNodus has zero references in this tree. Cloudflare Sandbox/Agents SDK and Vercel AI SDK are not dependencies of this Python FastAPI fork.

Apify (2026-08-14 continuation). Apify is already an overlay preset, not a missing product. hlt_extensions.py mounts https://mcp.apify.com when APIFY_TOKEN is set, and only for Deep web (firecrawl scope) or Audience — so research can reach forums and social that Firecrawl cannot. Production scraping stays Firecrawl. The weekly audience sweep asks for r/nursing, r/StudentNurse, and allnurses.com via that same scope, not via a CLI. Upstream's MCP retriever then lets the LLM pick 2–3 tools from every mounted MCP tool; Apify's hosted server exposes the whole store (search-actors, call-actor, RAG browser, …). That is the same lottery idea 5 already names for codegraph. There is no dedicated Allnurses actor in the Apify Store (2026-08-14 search); Reddit has several pay-per-event scrapers (e.g. trudax/reddit-scraper-lite). The Cursor “Ultimate Scraper” skill is an operator workflow (pick an actor, run it, save a file). It is not a second scraper to install in this FastAPI fork. This cloud VM has no Apify CLI and no APIFY_TOKEN; the Cursor Apify MCP in the session is a different door, for agents, not for Railway.

Past learnings. docs/solutions/ does not exist. Nothing in the Compound Engineering corpus could be reused.

External context. Other overlay-on-fast-upstream projects add watched-file annotations on sync PRs (this repo already lists four paths, but only as inert prose). InfraNodus is a text-network / gap-detection MCP meant to consume research output, not replace a researcher. CodeGraph's default-single-tool plus env allowlist is the usual way to stop MCP retrievers from flooding context. Upstream GPT Researcher v3.5.1 (June 2026) already ships MCP tool names that match this fork. Cloudflare and Vercel sandboxes are places agents run and then call MCP tools — not packages to install inside a research server.

1 Overlay contract as code

Stop treating “we stay close to upstream” as a full-tree merge plus a comment. Publish a machine-readable overlay manifest (the four watched paths already listed in the Monday workflow, plus the app.py install stamp, firecrawl, Langfuse, and any in-tree GPTR patches). The weekly PR then grades which of those paths actually changed, asserts the install hook still ran, and fails CI if a leaf module imports hlt_extensions. Conflicted merges still open a PR; clean weeks still stay similar to Assaf — they just stop relying on someone remembering the checklist.

Illustrative: the weekly job still pulls theirs; the overlay becomes a graded contract instead of a grocery list.

Axis
Upstream sync hygiene
Basis
direct: upstream-sync.yml lists overlay files as inert PR-body bullets and skips HLT tests when conflicts != ''. hlt_extensions.py says if app.py is regenerated, re-add the one import. AGENTS.md says leaves never import hlt_extensions, with no test enforcing it.
Rationale
This is the actual “stay up on theirs, keep ours on the side” mechanism. Without a contract, Monday work spends equal attention on CSS and on the docking fuse that, if dropped, silently kills /health, /gather, and Brain.
Downsides
The manifest must be kept honest as HLT grows into firecrawl, Brain UI, and mcp_server/ — those already sit outside the hlt_* prefix. A wrapper entrypoint that never touches app.py is a later variant, not required for this direction.

2 One research envelope Katailyst can bind

Do not grow the FastAPI process so “all our stuff is inside the researcher.” Katailyst already has three doors. Make them return the same envelope: scopes applied, presets expanded, research_id, sources, report, library hits. Generate GET /api/hlt/capabilities (and the Katailyst capability doc) from the live tool list so the registry cannot omit get_research_images again. Add a /gather?mode=report path so Create-hub does not have to hand-sequence deep_research then write_report. Point orchestrate and Cleo at MCP / /gather, never at REST /api/quick_search, if they need codegraph.

Illustrative: “easily use it” is a shared envelope, not more product stuffed into FastAPI.

Axis
Katailyst consumption
Basis
direct: scripts/katailyst_capability.md lists five MCP tools; mcp_server/tools.py registers six, including get_research_images. /gather returns findings and external_scan_id: None with no research_id. REST /api/quick_search is the documented web-only exception.
Rationale
If Create-hub or orchestrate hits the cheap REST door, codegraph never mounts and “all our stuff is inside the researcher” is a lie in practice. A generated manifest plus one envelope is how K2 stays honest as scopes grow.
Downsides
A single K2-native research verb with the five upstream names as a facade is a later variant; the five tools have different signatures and a stateful handoff, so do not collapse them until the envelope exists.

3 Runtime status of forces

Cloudflare Sandbox SDK, Cloudflare Agents SDK, and Vercel AI SDK are caller options. They do not belong in this Python tree. Cleo stays on Hermes with the locked Slack toolset (no execute_code, no terminal, no computer use). Any future sandboxed execution lives in another process whose network allowlist is Mastery Research MCP + codegraph + Katailyst2. Freeze a versioned MCP tool schema as the only integration surface those runtimes need. Add a CI check that fails if those packages ever land in pyproject.toml or the Next app's dependencies.

Illustrative: the attached SDKs are where agents run; this repo stays the cited-research lab they invite.

Axis
Agent runtimes
Basis
direct: Slack toolset excludes host execution because anyone who can mention Cleo would get code execution on the container. pyproject.toml has no sandbox/agent SDK packages. external: Cloudflare and Vercel sandboxes are framed industry-wide as execution hosts that call MCP, not as research-server internals.
Rationale
This answers the attached SDK skills without migrating Cleo off Hermes or turning Mastery Research into an agent host — which would fight upstream and the overlay rule.
Downsides
Sandboxed charts or executable artifacts still need a home; that home is a sibling worker, not a pip install here. Do not wait for that worker before freezing the MCP schema.

4 InfraNodus after the report, not beside the retriever

InfraNodus is not a second researcher and not a peer of GitNexus. On report_complete, optionally push the finished prose through InfraNodus's hosted MCP (gap detection / text network) and store “what this report did not cover” next to the library entry. Those structural holes can seed the suggestion strip and the next deep_research query. If a preset is ever added, it must be readiness-gated hosted HTTP like Apify — never a browser npx sample. Do not add InfraNodus to the MCP retriever's tool lottery.

Illustrative: two graphs, two times. Code MRI during the run; gap PET on the finished prose.

Axis
Graph layers
Basis
direct: search_prior_reports is keyword overlap, cheap by design. Repo-wide InfraNodus matches: zero. external: InfraNodus MCP is built for structural gaps and GraphRAG over existing text, not crawling.
Rationale
This is the one InfraNodus shape that honors “consider it” without replacing the researcher or competing with codegraph inside the tool picker.
Downsides
Vendor lock and data-handling (doNotSave exists on their API). Library JSON grows. If the hosted MCP is down, research must still complete.

5 One codegraph instrument on the tray

Mounting the codegraph server is not the same as selecting GitNexus. Upstream's MCP retriever lets the LLM pick two or three tools from all mounted MCP tools, while the sidecar exposes a full tray (query, context, impact, trace, source search, …) on a memory-bound box. For codebase scope, default the overlay to one allowlisted tool (and an env var to widen it). Keep hlt-codegraph as-is; do not move analyze off the disk-owning service — that idea is already rejected in reindex.sh because Render disks are single-service. The same allowlist pattern applies to Apify when Audience/Deep web mounts mcp.apify.com: pin a named actor (Reddit scrape for the weekly sweep) instead of handing the LLM call-actor against the whole store. Firecrawl remains the default page scraper; Apify is the forum/social specialist, not a second generic crawler.

Axis
Graph layers
Basis
direct: gpt_researcher/retrievers/mcp/retriever.py selects 2–3 tools from all available MCP tools. Codegraph registers about ten @mcp.tool() entries. No CODEGRAPH_MCP_TOOLS allowlist exists today.
Rationale
This is how Katailyst actually gets codegraphs through the researcher without turning Auto/codebase into an OOM lottery.
Downsides
A too-tight default may hide impact/trace when those are the right tools. The allowlist should be overlay-side so upstream retriever code stays untouched.

6 Freeze the two-door overlay API

Matching upstream tool names is compatibility. Matching upstream semantics is not required. Freeze this as the overlay contract: MCP quick_search / deep_research with scope=auto may escalate into presets (codegraph, Katailyst, …); REST /api/quick_search never does. Test both. When a browser-supplied stdio MCP config is dropped because this container has no Node and one failing stdio poisons the run, put that drop on the run payload the UI and Katailyst can see — not only in a server log.

Axis
HLT overlay surface
Basis
direct: mcp_server/tools.py escalates estate scopes to a short research pass so Katailyst2/GitHub actually fire. hlt_extensions.py documents REST as the web-only exception. Stdio configs are dropped with a warning; the frontend never reads dropped_mcp_configs.
Rationale
“Keep much similar” is about Assaf's product remaining recognizable, not about accidentally teaching generic gptr-mcp clients that REST and MCP behave the same. Loud drops stop silent under-delivery.
Downsides
A generic client pointed at the hosted MCP URL inherits HLT estate behavior. That is desirable if documented; surprising if not.

7 Make pack-load and persona registration observable

Cleo's boot is supposed to fetch agents.runtime_pack first, then fall back to registry_agent_context. Today that order is a prompt hint, not an observed health signal — so a degraded pack looks like “Cleo being weird.” Meanwhile docs and render.yaml describe AGENT_ID=brian, but AGENT_REFS only registers Cleo, so Brian boots without a registry ref and never gets the pack-load instruction. Register every on-disk persona, fail loud on unknown AGENT_ID, and report which K2 verb actually fired on /health.

Axis
Agent runtimes
Basis
direct: AGENT_REFS = {"cleo": "agent:cleo@v1"}; agent_ref() returns None for brian. K2_PACKET_LOAD_ORDER is written into a client hint only. Slack toolset lockdown is already persona-agnostic; the missing piece is the K2 routing contract per grounding/ directory.
Rationale
Katailyst cannot “easily use” research if the Slack body is silently running without its compiled pack. This is the smallest move that makes the current Cleo/K2 design honest in production.
Downsides
Registering Brian without a live K2 census row would still fail the pack fetch; the health signal should distinguish “persona unknown here” from “K2 has no cleo/brian yet.”

Continuation: Apify Ultimate Scraper

Verdict: useful as a Cursor operator skill and as a pinned actor on the existing Apify MCP preset. Not useful as a new thing to build inside this repo.

Where it already lives: Deep web and Audience scopes append {"name": "apify", "preset": "apify"} when a token exists. That is the right door. Where it should not live: a second scraper package, an apify-cli in the Railway image, or letting research-time LLMs shop the whole Actor store.

If the weekly audience sweep still comes back thin on Reddit, the next concrete move (after idea 5's allowlist) is to name one actor — trudax/reddit-scraper-lite is the high-use community option — and cap spend. Allnurses has no Store actor; keep Firecrawl there. Do not run paid scrapes from this environment until that pin exists.
